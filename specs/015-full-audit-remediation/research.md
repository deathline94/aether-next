# Phase 0 Research — Full-System Audit Remediation

**Feature**: `015-full-audit-remediation` | **Date**: 2026-09-21
**Method**: six parallel research workstreams (QUIC/H3, smoltcp, Windows system + trust, crypto/secrets/storage, Tauri contract + visual system, Android + supervision, CI/build), each required to return *Decision / Rationale / Alternatives considered / Verification test*. External claims verified against the vendored dependency sources in this repo where possible.

Every decision below names the test that would **fail if the guard were unreachable**. That requirement exists because this repo's recurring defect is a fix whose enabling condition can never fire (`specs/014/tasks.md` is 40/40 complete while several of its guards are inert).

## Corrections to the audit this plan remediates

Research against the vendored `quiche` 0.29.2 source disproved two audit findings and confirmed a third pair of attributions. They are recorded in `spec.md` §Clarifications and repeated here because they change the work:

1. **`Error::BufferTooShort` does not wedge inbound datagrams.** `dgram_recv` pops before comparing lengths (`quiche/quiche/src/lib.rs:6802-6816`), so one datagram is lost and the queue drains. The retained defect is different and still real: `enable_dgram(enabled, recv_queue_len, send_queue_len)` takes **entry counts** (`lib.rs:1198-1208`), while `aether/src/tls.rs:182` passes `65536, 65536` — permitting ~65 536 queued datagrams (tens of MB) — and `quic.rs:844-873` turns every non-`Done` receive error into a silent `break`.
2. **The recent CI signing commits created the defect, they did not fix it** (sign-after-bundle; verify-the-wrong-artifact).
3. **Confirmed as reported**: `Error::Done` from `dgram_send` means "send queue full" and the code destroys the packet (`quic.rs:66-79`); `flush()` must follow `send_ack_eliciting()` because the latter only sets a flag (`lib.rs:6744-6750`, emission gated at `:8268`); quiche's effective idle timeout is `min(local, peer)` floored to 3×PTO (`lib.rs:8897-8928`), so the 120 s local value is both shortened by peers and far beyond typical NAT soft state.
4. **Newly discovered during planning**: `dwProvFlags: 0x00000080` at `lib.rs:936` is labelled `WTD_REVOCATION_CHECK_NONE` but is `WTD_REVOCATION_CHECK_CHAIN_EXCLUDE_ROOT` (none is `0x40000`) — so CI's ephemeral certificate additionally undergoes a revocation check that cannot succeed; and 5 of 10 registered Tauri commands are never invoked by either frontend.

## A. Transport correctness (QUIC / HTTP3 / MASQUE)

### R1 — Inbound datagram path
**Decision.** Read datagrams with `Connection::dgram_recv_buf()` in a loop terminated **only** by `Error::Done`; every other `Err` is fatal. Delete the 65 535-byte scratch buffer. Set `config.enable_dgram(true, 2048, 2048)` to match `NET_QUEUE`. Gate every send on `conn.dgram_max_writable_len()` and treat `Error::Done` on `dgram_send` as a counted backpressure event, not a dropped packet. Cap the H3 path at MTU 1280.
**Rationale.** `dgram_recv_buf` (`lib.rs:6825`) returns `F::DgramBuf`, which is `Vec<u8>` under `DefaultBufFactory` (`buffers.rs:76-86`) and is already allocated at ingress (`data.into()`, `lib.rs:8852`) — so it is strictly cheaper than the copy-based `dgram_recv`. Quiche itself discards the oldest queued datagram over the receive quota (`lib.rs:8847-8850`), which is RFC 9297's silent-drop policy; the in-tree reference driver does exactly this drain shape (`tokio-quiche/src/http3/driver/datagram.rs:127-133`, `driver/mod.rs:1102-1114`).
**Alternatives considered.** Enlarge the read buffer to 65 536 (upstream `tests.rs:8510`) — rejected: still copies and leaves the queue-depth misconfiguration. `dgram_recv_peek`/`dgram_recv_front_len` loop — rejected: reimplements an API the fork already provides.
**Verification.** `drain_survives_undersized_reader`: a `Pipe` peer sends a 4 000-byte then a 64-byte datagram; assert the second reaches `inbound_tx`. With `dgram_recv_buf` the buffer size becomes unobservable, so the test cannot pass vacuously.

### R2 — Readiness classification and interim responses
**Decision.** Inside `poll_h3`: ignore any `:status` where `stream_id != req_stream`; parse the three digits — `1xx` → log and continue; `2xx` on the request stream → latch ready once (`final_response_seen`); any second final response or `3xx`+ → fatal `Masque`. Accept `dgram_by_peer` only after the iteration's `poll()` returns `Done` (SETTINGS can land in the same batch). If auto-negotiation resolves to QUIC-datagram but `dgram_max_writable_len()` is `None`, fall back to capsules instead of probing blind.
**Rationale.** RFC 9114 §4.1 permits a response to consist of multiple messages only when interim (1xx) responses precede a final one; RFC 9110 §15.2 makes 1xx provisional. The fork models 103 as a separate `Event::Headers` (`h3/mod.rs:4413-4465`, test `informational_response`), so today's `!status.starts_with('2') → Err` kills any tunnel behind an edge that sends Early Hints. Peer datagram support requires both the SETTINGS bit and a writable-len (`h3/mod.rs:1764-1769`).
**Alternatives considered.** First-headers-wins; treating any 2xx as authoritative — both rejected, they are the current bug. Using `more_frames` as the final marker — rejected: it reflects `!stream_finished()`, and CONNECT streams stay open forever by design.
**Verification.** Pure-unit `classify_status` table (off-stream 200 → Ignore; 103 → Interim; request-stream 200 → Ready; second final → Fatal) plus a `Pipe` test where 103-then-200 reaches `tunnel_ready`.

### R3 — Error taxonomy at every swallow point
**Decision.** `conn.recv`: `Ok` continue, `Err(Done)` benign, any other variant → `conn.close(false, 0x1, …)` (0x101 for `TlsFail`), flush, return `Err`. `flush`: keep `Done → break`, propagate everything else after closing. Socket `WouldBlock` → break and re-arm on `conn.timeout()`. Add a `dgram_send_dropped` counter; `BufferTooShort`/`InvalidState` on send are permanent and fail the mode negotiation rather than silently eating packets.
**Rationale.** quiche documents that `recv` closes the connection on error (`lib.rs:2805-2806`) and `h3::poll` likewise (`h3/mod.rs:2046-2047`); the reference loop is `apps/src/bin/quiche-server.rs:565-577` with garbage collection on `is_closed()`. `Error::to_wire()` is `pub(crate)`, so the application must choose codes. `Error::BufferTooShort` doubles as quiche's generic octets error (`error.rs:246`) and must never be treated as retryable. Note the crate's own anti-pattern list: `h3::Error != quiche::Error`.
**Alternatives considered.** Log-and-continue everywhere — rejected: after a protocol error quiche stops queuing packets, so the loop spins to idle timeout, which is exactly the observed zombie behaviour.
**Verification.** `recv_reports_protocol_error_as_fatal`: feed a mutated post-handshake packet; assert `run()` returns `Err` with `conn.is_closed()` — today it returns `Ok(())`.

### R4 — Local teardown vs peer teardown
**Decision.** Track an explicit `closing: bool` set only by local shutdown paths; `run()` returns `Ok(())` **only** when `closing` is true. Every other close reason returns `Err`, so `session.rs` records a failure rather than `record_success`.
**Rationale.** `quic.rs:627-680` returns `Ok(())` on any closed connection, and `session.rs:222-226` consequently rewards the peer that killed the tunnel; `masque_h2.rs:600-603` mirrors it. This single change removes the largest source of cache poisoning.
**Alternatives considered.** Heuristic "was it clean-ish" classification from the close error code — rejected: too many paths already collapse the distinction upstream.
**Verification.** Unit test: peer-initiated `close` → `run()` is `Err`; local `eof`-driven shutdown → `Ok(())`.

### R5 — Keep-alive, idle timeout and dead-peer detection
**Decision.** Keep a 15 s ack-eliciting ping, require `flush()` in the same iteration, treat `InvalidState` as dead-path. Record `conn.stats()` deltas; two consecutive unanswered pings tear down. `set_max_idle_timeout(45_000)` so idle teardown ≈ 3× the keepalive; keep `AETHER_QUIC_MAX_UDP_PAYLOAD ≤ 1350`.
**Rationale.** `send_ack_eliciting` only sets `path.needs_ack_eliciting` (`lib.rs:6744-6750`); the packet is emitted by the next `send()` (`:5343-5354`, gated `:8268`), so without a flush it is a no-op. Effective idle timeout is `min(local, peer)`-of-nonzero floored to 3×PTO (`lib.rs:8897-8928`): 120 s is both silently shortened by stricter peers and far beyond ~30 s NAT soft state.
**Alternatives considered.** Relying on PTO probes — rejected: PTO only fires with outstanding data. A synthetic datagram ping — rejected: PING is cheaper and quiche retransmits it correctly.
**Verification.** `keepalive_ping_reaches_peer` (server-side packet counter grows over two intervals) and `dead_peer_tears_down_within_idle_timeout` (stop delivering in the `Pipe`; assert return within ~45 s with a non-`Ok` reason).

### R6 — Scanner timer promptness
**Decision.** One task per probe via `JoinSet` with `buffer_unordered(concurrency.min(16))`; each task's `select!` is `biased` with the `sleep(conn.timeout())` arm first. Move **all** persistence off workers: probes emit outcomes on an `mpsc`, one `spawn_blocking` task writes with a 500 ms / 64-outcome debounce. Remove `std::thread::sleep` from the probe path entirely.
**Rationale.** quiche is app-timer-driven, so a starved worker means expired timers and inflated PTO. Cloudflare's own driver documents the identical ordering rule ("otherwise we could theoretically starve the sleep arm and hang connections", `tokio-quiche/src/quic/io/worker.rs:316-322`, deadline computed as `min(qconn.timeout_instant(), …)` at `:296-306`). Today's blockers are a 15 ms × up-to-1500 ms lock spin (`cache.rs:144-182`) and up to 8 × 20 ms rename retries (`:341-377`), on ≤8 workers with 8-16 probes.
**Alternatives considered.** More tokio workers / a bigger blocking pool — rejected: masks starvation. `tokio::time::sleep` on the lock — rejected: still serialises probes behind 1.5 s.
**Verification.** `probe_timer_is_prompt_under_contention`: pre-create the cache lock file, measure the maximum gap between successive `on_timeout()` calls across 8 probes, assert < 20 ms (≥1500 ms today).

## B. Netstack, proxies and system network

### R7 — Idle connections: keep-alive plus a bounded abort
**Decision.** Keep `set_timeout(Some(10s))` at connect. On transition to `Established`, set `set_timeout(Some(75s))` **and** `set_keep_alive(Some(15s))` (75 > 4×15). Existing `Closed && established` cleanup reaps the peer.
**Rationale.** Keep-alive is genuinely implemented in 0.12 — `set_keep_alive` (`smoltcp/socket/tcp.rs:760`) arms `Timer::Idle{keep_alive_at}` (`:318-330`), `dispatch` emits a 1-byte probe at `seq-1` when nothing else is pending (`:2448-2455`) and rewinds (`:2498`); the peer's ACK refreshes `remote_last_ts` (`:1932`) so `timed_out` (`:2118-2122`) cannot fire on a live idle peer, while `poll_at` returns the keep-alive deadline (`:304-315`) so `iface.poll_delay` wakes for it.
**Alternatives considered.** `set_timeout(None)` on Established — rejected: makes the stack unsupervised, leaking sockets and slots on half-open peers. A wrapper-side last-activity watchdog — rejected: duplicates smoltcp's bookkeeping and still needs a probe packet to distinguish "idle" from "dead".
**Verification.** Monotonic time first (the loop's `Instant::now()` at `netstack.rs:457` is wall-clock and makes the guard untestable). Then: reach Established, advance the simulated clock 60 s with zero inbound, assert still `Established` **and** ≥1 egress frame observed — the frame assertion is what fails if keep-alive is a no-op.

### R8 — Bounded device TX with correct exhaustion semantics
**Decision.** Cap `device.tx` at `TX_RING = 256`; `transmit()` returns `None` at capacity and increments `tx_deferred`. Leave `receive()`'s paired token uncapped. Floor the loop sleep at 1 ms when the ring is full. Replace fixed per-socket buffers with a global 128 MB admission budget (1 MB rx / 256 KB tx while ≥16 MB headroom, else 128 KB / 64 KB); UDP 128×256 KB unchanged.
**Rationale.** Returning `None` is the contract's exhaustion signal: `socket_egress` maps it to `EgressError::Exhausted => break, // Device buffer full` (`iface/interface/mod.rs:668-671,745`), and because `emit(...)?` in `dispatch` runs *before* `remote_last_ack/remote_last_seq` are updated (`tcp.rs:2494-2521`), the segment is retried rather than lost. Dropping an ingress-triggered **ACK** is unsafe: `ack_reply` updates `remote_last_ack` eagerly (`tcp.rs:1383-1391`) and a lost reply is not regenerated until new data or a window update — hence the asymmetry. `set_send_buffer_size`, `set_tx_buffer` and `Socket::pause` **do not exist in 0.12** (verified by grep of the crate source), so buffer-shrink and pause-based backpressure are unavailable, not merely undesirable.
**Alternatives considered.** Drop at flush — rejected: violates order and invites retransmit storms. 512×2 MB fixed — rejected: ~1 GB, the documented abort mode.
**Verification.** Saturate `outbound_tx` (capacity 1), poll until growth stops, assert `tx.len() ≤ TX_RING+32` and `tx_deferred > 0`; then drain and assert the peer received every byte in order with no permanent stall.

### R9 — Strict FIFO on the outbound path
**Decision.** Delete the `ACKISH`/`deferred` split (`netstack.rs:817-852`); pop strictly FIFO into `outbound_tx`, `push_front` the single refused frame and return.
**Rationale.** One TUN queue means per-flow order is mandatory, and "≤128 bytes" cannot distinguish a pure ACK from a small PSH segment (SSH keystrokes, HTTP requests) — so a later small frame overtakes an earlier 1448-byte frame on the same connection, producing dupACKs and spurious fast-retransmit/reorder-timeout. ACK starvation is already structurally bounded: `socket_egress` emits at most one packet per socket per poll (`iface/interface/mod.rs:657`), and the bounded ring caps ACK latency at ~256 frames. Content-based pure-ACK classification is computable from the bytes present (IPv4 `ihl`/`proto`/`data_off`/`flags`) but is deferred rather than adopted because promoting a *smaller* window or older ACK ahead of newer state is its own hazard.
**Alternatives considered.** Keep size-based priority with a per-flow sub-queue — rejected: complexity disproportionate to a non-defect.
**Verification.** Mixed-size property test: `[1448, 52, 1448, 60, 1448]` through `mpsc(1)`, flush to exhaustion, assert pop order equals push order. The existing test (`netstack.rs:859-917`) uses only large frames and can never fail on this bug — that is the point.

### R10 — Loop fairness and timely device polling
**Decision.** Drop `biased` from the main select (`netstack.rs:499`) so branch order randomises. Replace `iface.poll()` with bounded interleaving: `poll_ingress_single` ≤32 times, then one `poll_egress` pass. Per-tick budgets: cmd ≤64, data ≤128, ingest ≤batch. Floor `poll_delay` at 250 µs when the ring is full; `delay.unwrap_or(250ms)`.
**Rationale.** `poll()` drains all ingress before any egress (`iface/interface/mod.rs:449-462`) and its own documentation recommends `poll_egress`/`poll_ingress_single` for interleaving (`:430-435`). `biased` guarantees branch-1 priority, which is precisely the starvation mechanism. `poll_delay` is advisory — `None` means "wait for ingress only", so the existing `sleep_opt(None)` is correct (`iface/interface/mod.rs:529-570`).
**Alternatives considered.** A hand-written `poll_fn` budget ledger — rejected: more code, no measured gain over randomised select. A priority channel for cmd — rejected: hides rather than fixes starvation.
**Verification.** Preload inbound with 5× the batch budget and assert a concurrent `Cmd::OpenTcp` completes within ≤10 iterations (instrumented counter). Fails today.

### R11 — Panic containment without a stack restart
**Decision.** Add non-panicking accessors `with_tcp`/`with_udp` implemented over `sockets.iter_mut()` matching handle and variant; use them everywhere `get::<T>()`/`get_mut::<T>()` appears today. Extend the existing `catch_unwind` to cover `handle_cmd`/`handle_data`, and stop clearing `rx`/`tx` on recovery. Keep the `JoinHandle` so `wait_stack_alive` can own a restart only when the **task** exits.
**Rationale.** smoltcp 0.12's `SocketSet` exposes **only** panicking `get`/`get_mut`/`remove` (`iface/socket_set.rs:98-130`) — there is no `get_checked`/`query` in this version, so a wrapper-side scan is the only non-panicking option. For a VPN, restarting the stack kills up to 512 live flows and is strictly worse than a scoped catch; `panic = "unwind"` is set in `[profile.release]`, so the catch is real.
**Alternatives considered.** Restart-on-panic — rejected as above. `catch_unwind` on the whole loop including socket access, without fixing the accessors — rejected: it converts a recoverable event into the very restart we refuse.
**Verification.** Remove a socket handle while leaving its `tcp_conns` entry, then issue `handle_cmd(OpenTcp)` + `service_tcp`: assert no panic escapes, buffers untouched, task not finished, and a subsequent `open_tcp` still succeeds.

### R12 — Source-port randomisation and quota partitioning
**Decision.** Seed `next_port = 49152 + random % 16384` once per stack; advance with an **odd** stride (`((random | 1) & 0x1FFF).max(17)`) so it is coprime with the 2^14-wide band and cycles it fully; `alloc_unique_port` retries ≤64 times against a `HashSet<u16>` of live ports. Add a resolver/proxy class flag to `Cmd::OpenUdp`/`OpenTcp` with per-class caps: UDP 96 proxy / 32 resolver; TCP 480 proxy / 32 resolver.
**Rationale.** Sequential ports (`netstack.rs:405,414-418`) make DNS query-ID/source-port guessing cheap. Capacity is **not** compile-time in this design: `SocketSet::new(Vec::new())` (`netstack.rs:401`) is the growing owned variant (`iface/socket_set.rs:82-90`), so a runtime per-class counter suffices — no second `SocketSet`, no `Arc<Semaphore>` double-bookkeeping.
**Alternatives considered.** Random port per allocation — rejected: O(n) collision scans against live sockets. Separate `SocketSet` per class — rejected: doubles the fixed cost for no behavioural gain.
**Verification.** Open 100 proxy UDP sockets to exhaustion, assert `dns_resolve` still succeeds. Sample 1 000 allocated ports: all in band, all unique against live sockets, consecutive-difference stddev > 100 (fails on the current +1 counter).

### R13 — Proxy surface policy
**Decision.** One env gate (`AETHER_ALLOW_REMOTE_PROXY`); delete `AETHER_UNSAFE_PUBLIC_PROXY`. Loopback-only fail-closed by default. If remote is enabled, require a per-session credential. Enforce a post-resolution destination deny-list at the single netstack choke point: `127.0.0.0/8`, `::1`, `0.0.0.0/8`, `169.254.0.0/16` (IMDS), `100.64.0.0/10`, `fc00::/7`; RFC1918 opt-in only.
**Rationale.** Two different variables gate one behaviour today (`socks.rs:47`, `http_proxy.rs:16` vs `engine_config.rs:69`), so neither is reliably off. Any local process can currently `CONNECT 169.254.169.254` **into** the tunnel, i.e. at the exit provider's metadata service — the deny-list belongs at the single point that has resolved the destination. This matches the fail-closed defaults of mihomo/sing-box class exit proxies plus loopback binding.
**Alternatives considered.** Per-handler checks — rejected: the DNS-rebinding path re-resolves after the check, so only post-resolution is sound.
**Verification.** `CONNECT 169.254.169.254:80` through both listeners is refused; setting only the deleted legacy variable has no effect.

### R14 — Host network mutation without shell-outs
**Decision.** Replace all route/adapter mutation with `netioapi` FFI (`CreateIpForwardEntry2`/`DeleteIpForwardEntry2`/`GetIpForwardTable2`, keyed on `InterfaceLuid` + `DestinationPrefix` + `NextHop`, with `Protocol == MIB_IPPROTO_NETMGMT`), write a `routes.journal.json` **before** mutating, refuse global deletion when identifiers are absent (match next-hop == recorded tunnel address instead), and run `route_repair::run_unconditionally()` as the first action of shell startup regardless of routing mode, plus a `--repair-routes` CLI for the uninstall path.
**Rationale.** Microsoft documents `ifIndex` as non-persistent ("may change… should not be considered persistent") and the LUID as the stable identity (`MIB_IPFORWARD_ROW2`). Three `powershell.exe` cold starts (1-2 s each) cannot fit a 5 s grace window, which is the mechanical cause of the blackout; FFI removes the dependency entirely.
**Alternatives considered.** `Remove-NetRoute -NextHop` — rejected: still three shell starts. A Windows service or scheduled task — rejected: adds a persistent attack surface for users who never use TUN. Job-object "graceful close" notification — rejected: `KILL_ON_JOB_CLOSE` is `TerminateProcess` with no pre-notification.
**Verification.** Decoy `0.0.0.0/1` on a second interface + zeroed journal LUID → decoy survives. `taskkill /F` the engine → decoy survives, Aether routes clear at next start. Teardown < 500 ms with `powershell.exe` removed from `PATH`.

### R15 — Who owns host mutations
**Decision.** The GUI (already elevated in TUN mode) owns route and proxy mutations; the engine receives a `DuplicateHandle` of the GUI process handle and `WaitForSingleObject`s it, so an in-session teardown handshake occurs before any `kill()`; the job object stays as the backstop; grace period 5 s → 15 s. Route lifetimes are additionally set as a 90 s lease refreshed every 30 s.
**Rationale.** Moving mutation ownership inside the process that can be hard-killed is the root cause; a parent-handle wait gives the child a deterministic pre-death signal, and Windows route `ValidLifetime` provides self-expiry as a fourth layer.
**Alternatives considered.** Engine-owned mutation with a heartbeat file — rejected: still races a hard kill. Lifetime lease alone — rejected: 90 s of blackhole is not acceptable as the primary mechanism, only as a backstop.
**Verification.** Kill the GUI (not the engine) and assert the engine tears down within the handshake budget; kill the engine and assert repair fires on next start.

### R16 — wintun.dll resolution
**Decision.** Delete the `AETHER_WINTUN` env path and the CWD-relative fallback. The verified parent passes an absolute canonicalised path as the first stdin control token. Engine startup calls `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` and loads with `LoadLibraryExW(LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32)`; verification (pinned SHA-256 + publisher) happens **before** load, using the `wintun` crate's `verify_binary_signature` feature. The GUI's check becomes mandatory, not `if let Some`.
**Rationale.** An elevated process honouring a user-writable env var or CWD for `LoadLibrary` is privilege escalation by construction; `verify_binary_signature` performs `WinVerifyTrust` VERIFY→CLOSE plus a signer-name check without executing `DllMain`, which resolves the verify-before-load ordering problem. `AddDllDirectory` alone does not constrain dependency resolution.
**Alternatives considered.** Inspect exports first — rejected: requires loading. Rely on the GUI's check only — rejected: the check is currently skipped exactly when the packaged file is missing.
**Verification.** `AETHER_WINTUN=<trojan>` → connect fails **and** the DLL's `DllMain` flag file is never created. Unsigned `wintun.dll` beside `aether.exe` → rejected in release.

## C. Trust, secrets and learned state

### R17 — SPKI pinning that still verifies the chain
**Decision.** Keep `set_verify_callback(SslVerifyMode::PEER, …)` but *perform* validation inside it: `ctx.verify_cert()? && pin_matches(host, leaf)`. Build trust anchors into an `X509Store` supplied via `set_verify_cert_store`. Replace the flat pin slice with `PinSet { host, require_hostname, pins: &[Pin{spki_sha256, expires_unix}] }`. Delete `set_verify_hostname(false)`: dial the pinned host for verification (`into_ssl(PIN_HOST)`) and set the fronting SNI separately, so `AETHER_MASQUE_SNI` keeps working. Require ≥2 pins per host (live + next key), check expiry at startup, and on failure emit `SessionEvent::Error` naming host, observed leaf SPKI hex, verify result and the expiry date.
**Rationale.** boring 4.22 exposes `X509StoreContextRef::verify_cert()` documented as working "only inside of a call to `init`" (`boring/src/x509/mod.rs:259-268`), and BoringSSL pre-initialises the store context with the chain, `"ssl_server"` and the SNI host before invoking the app callback (`boringssl/src/ssl/ssl_x509.cc:376-406`). boring's own documentation warns that legacy callbacks are hard to use correctly and should call `verify_cert` — while `set_custom_verify_callback` **cannot** merely add pins, because the callback replaces `session_verify_cert_chain` (`handshake.cc:366-386`). Cloudflare consumer MASQUE edges present a certificate not valid for the dialled address, which is why name validation must be pin-scoped rather than globally disabled.
**Alternatives considered.** Post-handshake verification with `peer_certificate()` + `rustls-webpki` — rejected: quiche offers no chain hook before CONNECT-IP is sent, and resumption would bypass it. `webpki-roots` as the anchor source — rejected: its `TrustAnchors` carry only subject/SPKI bytes and cannot rebuild an `X509Store`.
**Verification.** A self-signed leaf whose SPKI is pinned but whose pin has expired must be rejected — this fails immediately if `verify_cert()` is dropped from the callback.

### R18 — Removing the verification kill-switches; one config store
**Decision.** Delete both env variables. Thread an explicit `VerifyPolicy { Pinned(&'static [PinSet]), ReadOnlyProbe, Insecure{…} }` into the TLS builders; make `Insecure` exist only under `#[cfg(debug_assertions)]` (or a `dev` feature) so release has no such variant. Empty or fully-expired pin sets are a hard error. Make `runtime_env` the sole reader (no fallthrough to `std::env::var`), add `remove()` and a `Snapshot`, use `parking_lot` with `read().unwrap_or_else(|e| e.into_inner())`, and convert the remaining direct readers (`session.rs`, `lastconn.rs`, `masque_h2.rs`, `obfuscation.rs`, `wireguard.rs`, `tls.rs`). Truthiness becomes one helper used by every boolean flag (fixes `AETHER_WG_NO_DATA_CHECK=0` inverting).
**Rationale.** `cfg!(debug_assertions)` in a `const` folds to a literal under `--release`, so the branch is dead-code-eliminated; a runtime env check cannot be. Today `h3_probe.rs:252` writes through `runtime_env::set` while `tls.rs:128` reads `std::env::var`, making the control simultaneously **inert** (the fingerprint probe never works) and a **latent process-wide MITM switch** (one accessor change from live). Naming follows the ecosystem convention of an explicit `danger_*`/`--insecure` API rather than an ambient variable.
**Alternatives considered.** Keep the variables but require a value of `1` — rejected: still ambient, still settable by any local process. A separate debug binary with feature flags — rejected as the primary mechanism: the feature must not be *constructible* in release, which cfg gating gives for free.
**Verification.** Compile-fail test that `VerifyPolicy::Insecure` is unnameable in release; a release-mode test that setting both variables has no observable effect.

### R19 — Secrets at rest
**Decision.** Versioned envelope `AETHERCFG2 ‖ nonce(12) ‖ ciphertext+tag` with ChaCha20-Poly1305 and **AAD = canonical absolute path ‖ magic ‖ schema version**; nonce from `generate_nonce(&mut OsRng)`. `key()` becomes `KeySource::{Shell, DpapiFile, Keystore, None}`; with `None`, `save()` refuses to persist token/private key/PEM and writes only non-secret config. Plaintext is migrated on load by re-encrypting, verifying the read-back, and only then overwriting. Stop passing key material through `AETHER_CONFIG_KEY`; hand it once over stdin and remove it from the environment. `#[derive(ZeroizeOnDrop)]` on `Identity`, `Zeroize` on key arrays, `StaticSecret::random_from_rng(OsRng)`.
**Rationale.** AAD path-binding makes the existing cross-file replay (`aether-masque.toml` → `aether.toml`) impossible; `chacha20poly1305` supports AAD natively. `StaticSecret` already zeroizes on drop in `x25519-dalek 2.0.0-rc.3` (`x25519.rs:195-198`), but the surrounding copies do not. RFC 8439's 96-bit nonce must never repeat under one key, which random generation plus a fresh nonce per record satisfies.
**Alternatives considered.** `age`/`rage` — rejected: needs an identity file, reintroducing the unprotected-key problem. Delegating the whole file to DPAPI — rejected: no cross-platform parity and no AAD binding. Per-launch re-derivation — impossible: the WARP WireGuard key is server-enrolled.
**Verification.** Move a ciphertext from path A to path B → authentication fails.

### R20 — Atomic replacement without a trusted backup
**Decision.** Temp name `pid + seq + OsRng` bytes; on Windows use `ReplaceFileW(..., lpBackupFileName = NULL, ...)` so no `.bak` is created; delete both `std::fs::copy(path, &bak)` and the `.bak`-trusting branch in `load()`; on Unix fsync the file **and** the parent directory.
**Rationale.** `ReplaceFileW` creates a backup only when a backup name is supplied; the current failure path leaks the previous secret through a differently-ACL'd copy, and `load()` then restores it, turning a stray file into an identity-swap primitive.
**Alternatives considered.** Write `.bak` through the restricted writer — rejected: still a second plaintext copy that some path trusts.
**Verification.** Plant a `.bak` containing a foreign identity → `load()` must ignore it.

### R21 — File ACLs under elevation
**Decision.** Derive the principal from the process token (`OpenProcessToken` + `GetTokenInformation(TokenUser)`) or the active console session, never from `%USERNAME%`. Apply a protective descriptor via `ConvertStringSecurityDescriptorToSecurityDescriptorW` + `SetNamedSecurityInfoW(DACL_SECURITY_INFORMATION)` with `D:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;GRGW;<sid>)`. Better still, per R20/R15: the elevated child does not touch the identity file at all.

> **Implemented differently (2026-09-22).** The token-derived principal is exactly what ships; the *descriptor* is not, and was not the substitute this row assumed. `config.rs` restricts with `icacls <path> /inheritance:r /grant:r *<sid>:F` — one explicit grant, no inherited ACEs, no SYSTEM/Administrators entry — and `win_acl::protective_descriptor()`, which built the SDDL above, was reachable only from its own test and has been deleted. Narrower than this decision on purpose: DPAPI bounds who can read the *plaintext* to that same user, so `SY`/`BA` would only have enlarged the set that can read the ciphertext.
**Rationale.** `/inheritance:r` + `{USERNAME}:F` wipes inherited ACEs and grants the *calling* identity — under elevation that is the administrator account, so the next ordinary-user launch cannot read its own config and re-provisions a new device.
**Alternatives considered.** Credential Manager for the key — rejected: adds a 2 560-byte limit and a visible entry for no gain over DPAPI + entropy. NCrypt/TPM-protected key — rejected: cannot roam or survive reinstall, breaking the recovery path.
**Verification.** Run the engine as a second admin account → the ordinary user's GUI can still read its config, and the `Administrators` group cannot.

### R22 — Endpoint cache and cross-process locks
**Decision.** One `EndpointRegistry` task owns the data; all reads/writes are `mpsc` request/response; the file is a write-behind snapshot only. Schema `{version, written_at, entries[]}`; `successes` clamped to 1000; `saturating_add` everywhere; timestamps recorded as `(epoch_secs, monotonic_ticks)` with epoch validated (`ts > now + 300` rejects the entry) and all decay driven by the monotonic term. Entries must fall inside the compiled MASQUE/WG prefix allowlists. Corrupt files are kept as `.corrupt.<seq>`, never clobbered. Locking: `CreateMutexW` on Windows (kernel-owned, `WAIT_ABANDONED_0` on holder death) and `flock` on a permanent fd on Unix; never `remove_file` a lock; never fail open after a timeout; delete the dead `PROVISION_LOCK_STALE` constant and follow the existing `ProvisionGuard` model.
**Rationale.** `fs2` locks are advisory only (`fs2/src/lib.rs:42-49`), so "delete the stale lock file" is inherently racy — the repo already contains a correct hard lock and simply does not use it for the cache. Today the sorted getters read **without** the lock (`cache.rs:453-464`) and `load_endpoints` renames files from read paths.
**Alternatives considered.** Keep the lock file and fix its staleness logic — rejected: an advisory lock with a delete-the-file recovery path cannot be made sound. Sign the endpoint list server-side — rejected: no server capability exists, and local-learned-only trust plus "never prefer cached over freshly verified" removes the incentive.
**Verification.** A cache with a future timestamp, 2^31 successes and an address outside the prefix allowlist → all three rejected, ordering unaffected.

### R23 — WireGuard layer decisions
**Decision.** (a) **Delete** `preshared_key`: WARP enrolment returns none, and a nonzero PSK changes `k2`/`mac2` so the handshake becomes unpairable against Cloudflare. (b) Thread `persistent_keepalive` into the probe (it hardcodes `Some(25)` today and the `from_established` reuse path silently discards the configured value); cache established sessions with a TTL of `REJECT_AFTER_TIME − REKEY_TIMEOUT = 175 s` and LRU eviction instead of `clear()` at 4; `parking_lot::Mutex`. (c) Client-ID injection into the reserved bytes is **default-off**; when enabled, the tag is 3 random bytes per tunnel, never the account-stable `client_id`. (d) Clamp junk sizes to `[0, 512]` after parsing, keep totals under the path MTU, emit random 1-4-byte filler instead of a constant `0x00`, remap the decoy first byte to avoid the WG type range **and** the `+0x40` re-entry, and use `u16::try_from` for the IKEv2 payload length.
**Rationale.** boringtun MACs `dst[..mac1_off]` verbatim (`noise/handshake.rs:692`), so mutating the reserved bytes breaks `mac1` against any strict peer; the WG timers are `REKEY_AFTER_TIME = 120 s`, `REJECT_AFTER_TIME = 180 s` (`timers.rs:19-20`, matching RFC 8718). A `(0,0)` junk pair currently produces a *constant* byte, which is a stronger fingerprint than sending none.
**Alternatives considered.** Populate the PSK and probe consistently — rejected: the server side has no PSK to negotiate, so the field can only ever be wrong. Keep injection on by default — rejected: it is a cleartext cross-session identifier on every packet including thousands of probe packets.
**Verification.** `AETHER_NOIZE_JMAX=1e8` → every packet ≤512 B. With injection off, `mac1` verifies against a strict boringtun peer.

### R24 — Runtime trust anchor
**Decision.** Ship a committed, reviewed `packaging/trust/engine-trust.json` (filename, file SHA-256, certificate SHA-256, SPKI SHA-256) plus a long-lived self-signed code-signing certificate minted **once** (10 y) and stored as CI secrets, whose public DER hash is committed. `verify_elevated_binary` becomes: compare the leaf's certificate hash and SPKI hash to the pins → build a chain anchored *at the pinned leaf* (`CERT_STORE_PROV_MEMORY` + `CertAddEncodedCertificateToStore` + `CertCreateCertificateChainEngine` with `hRestrictedRootStore`) → `CertVerifyCertificateChainPolicy(CERT_CHAIN_POLICY_AUTHENTICODE)` → file digest. `WinVerifyTrust` is used only as a PE-digest check. Fix the mislabelled revocation flag and always `WTD_STATEACTION_CLOSE`. Release digests are written by the release job **after** signing, never by `build.rs`. Drop `allow_unsigned_in_debug`; gate any dev bypass on a compile-time-only option.
**Rationale.** Validating against the machine root store cannot work with a per-run self-signed cert, and hashing the file that is about to be shipped is self-referential. `windows-sys` 0.61 already exposes the required APIs. Signing after `build.rs` runs would invalidate any build-time hash — an independent reason digests must be post-signing artifacts. Honest economics: Azure Artifact/Trusted Signing is not free (paid subscription, ~$9.99/mo per 5 000 signatures, and the certificate CN must be a validated legal name), and SmartScreen reputation accrues per file hash regardless — so a plan that requires a paid EV certificate is a plan that will be skipped, which is itself the vulnerability.
**Alternatives considered.** Pin the file hash only — rejected: churns on every rebuild until reviewers stop reading it. Have the installer run `certutil -addstore TrustedPublisher` — rejected: turns the app into a root-of-trust installer. Read digests from a file next to the exe — rejected: the attacker swaps both.
**Verification.** Release TUN against a binary signed by a *different* `CN=deathline94` certificate must fail (proves the pin is reachable); a release-binary string scan finds no dev-trust branch; a mutation job overwrites the digest JSON with a wrong value and the runtime test goes red.

## D. Tauri contract, lifecycle, CI and supply chain

### R25 — Generated IPC contract
**Decision.** `tauri-specta 2.0.0-rc.x` + `specta` + `specta-typescript` + `thiserror`: derive `specta::Type` on `Settings`/`RuntimeState`/`SessionEvent`, replace every `Result<_, String>` with a typed `CommandError`, generate `bindings.ts` in CI and `git diff --exit-code`. Export numeric limits as constants (`Builder::constant("SCAN_MAX", 500)`). Convert the stringly allowlists into real enums (`IpVersion::{Auto,V4,V6,Dual}`), removing `"both"` and the `"thorogh"` typo from the type system. **For the third layer** (engine → shell JSON lines), stop matching on `serde_json::Value`: parse into a typed `SessionEvent` and re-emit the parsed value, so a new engine variant fails the shell's compile.
**Rationale.** tauri-specta v2 is Tauri-v2-only and generates commands, events (including scoped `listen`) and error types; `@tauri-apps/specta` does not exist on npm and is not required — the generated file imports only `@tauri-apps/api/core` and `/event`. serde's `rename_all = "camelCase"` is already in use (`lib.rs:227-228`) and specta honours it. `ts-rs` is types-only (no command or event signatures), `typify` goes the wrong direction, and hand-written `.d.ts` + a round-trip test is the status quo that produced `"both"`/`scan_failed`/2000-vs-500.
**Alternatives considered.** Keep hand-written types and add a parity grep — rejected as insufficient alone; retained only as a belt-and-braces check plus the reverse direction (R28).
**Verification.** CI regenerates bindings and diffs. Adding a Rust field without a TS update fails the build. Plus a Rust test asserting every `SessionEvent` variant is registered in the event collector, and **both-direction** IPC parity (R28).

### R26 — Where the watchdog lives
**Decision.** The authoritative deadline is in the **shell**: stamp the existing `generation: AtomicU64` at connect entry and spawn a 90 s sleeper that, if `connecting` is still set *for that generation*, kills the child and emits `error`. Add an engine `phase` heartbeat every ≤15 s and treat three misses as a stall. Keep a UI mirror timer. Scans carry `run_id` on every variant, injected into the child and echoed back; shell and UI drop non-matching events; the synthetic terminal event becomes a typed `scan_failed { run_id }`; `stop_scan_child` drains stdout to EOF (bounded) after `cancel` before `kill`. Fix `AETHER_SCAN` hardcoded to `"balanced"` by threading `scan_mode`.
**Rationale.** `watch_child` fires only on `try_wait() -> Ok(Some(_))`, i.e. process exit, so a hung-but-alive engine is unobservable from the shell today — and a JS-only timer cannot be trusted because WebView2 throttles timers in occluded/minimised windows, which this app deliberately enters on close. Echoed monotonic run tokens with non-matching discard is the established discipline (Jupyter `parent_header.msg_id`, LSP request ids). Android's existing `CONNECT_WATCHDOG_MS = 90_000` proves the pattern is understood and simply un-ported.
**Alternatives considered.** Frontend-only watchdog — rejected for the throttling reason. A per-command request id on every invoke — rejected as the primary mechanism: it fixes request/response pairing but not unsolicited status stalls.
**Verification.** Rust test with a fake engine that prints nothing and sleeps: `session://state` reaches `error` within 90 s. Frontend test: a `run_id: 1` hit arriving after scan #2 leaves the row count unchanged.

### R27 — Telemetry contract and the updater decision
**Decision.** Delete every unmeasured metric. `RuntimeState` carries only `{status, detail, pid, endpoint}` today, and a sweep of all 26 engine modules finds **no** byte/packet/loss/RTT counters — the only real measurements are per-hit `rtt_ms` and `tunnelping`. Add `handshake_rtt_ms: Option<u32>` and `active_endpoint_rtt_ms: Option<u32>`; TypeScript types are `number | null`, and `null` renders `—` with `aria-label="unavailable"`. **Do not implement a signed updater**: downgrade the banner to "a new version is available" plus an opener link.
**Rationale.** `tauri-plugin-updater` needs `createUpdaterArtifacts`, a literal minisign pubkey (not a path), endpoint templates and an `updater:default` capability, plus a CI-generated static manifest — and there is no key-custody story here, so the plugin would be configured incorrectly or not at all. The regex `/(\d+)\s*ms/i` can never match `test_connection`'s real return string (`lib.rs:1623`), so `< 45 ms` is a fallback, not a measurement. A security tool that invents status indicators teaches users to distrust the real ones (NN/g visibility-of-system-status; the same principle behind browser chrome rules that a security indicator must not misrepresent state).
**Alternatives considered.** Wire the sparkline to real data — rejected as scope creep: there is no data source; deleting is the honest fix. Implement the updater against GitHub Releases — rejected: rate limits/auth plus unsigned-key custody.
**Verification.** CI grep for the fabricated strings (`"0.0%"`, `"< 45 ms"`, `"TLS 1.3"`, `"LISTENING"`) must return nothing; a unit test asserting each stat renders `—` when its field is `null`.

### R28 — Shell lifecycle: poisoning, jobs, ownership
**Decision.** (a) `lock().unwrap_or_else(PoisonError::into_inner)` for `Mutex<RuntimeState>`, `Mutex<Option<JobHandle>>`, `Mutex<Option<ProxySnapshot>>`; for `Mutex<Child>` **remove the mutex instead**. (b) One `engine_supervisor` thread owns `Child` + `Job` behind an `mpsc` command channel; `Job` becomes a non-`Copy` RAII owner whose `Drop` kills and closes; assignment failure is fatal to `connect` (today it only `eprintln!`s and continues); the scan child gets its own job. Never set `BREAKAWAY_OK`/`SILENT_BREAKAWAY_OK`; rely on Windows 8+ nested jobs for grandchildren. Bound any future restart policy (e.g. 3 per 60 s). (c) Keep "GUI must be elevated" for TUN rather than a `runas` spawn.
**Rationale.** A job member spawned through a different token/UAC broker produces a process `AssignProcessToJobObject` cannot control, so an `elevated runas` child escapes kill-on-close — which is why the current design must not move to `Start-Process -Verb RunAs`. `into_inner` is sound for plain values and RAII owners, and unsound for a half-closed `Child` handle, hence the ownership change rather than a blanket lint fix.
**Alternatives considered.** `parking_lot` everywhere — rejected: removes poisoning but hides real invariant breakage on `Child`/`Job`. `catch_unwind` per task with `Mutex<Child>` — rejected: same half-closed-handle problem. A SYSTEM service with a named pipe (the WireGuard-for-Windows pattern) — accepted as phase 2, not phase 1.
**Verification.** Test that panics a stdout worker while it holds `operation`, then asserts the supervisor still reclaims and kills the child. Grep gate: no `Job::create()` result discarded, and every `Command::spawn()` within one line of an assign-child call.

### R29 — Windows package signing pipeline
**Decision.** Make Tauri the signer rather than signing after it: import a **stable** PFX from secrets (not a per-run mint) → `cargo build --release` engine → sign `aether.exe` → stage → `npm ci && npm run build` → `npm run tauri build -- --config '{"bundle":{"windows":{"certificateThumbprint":"…","digestAlgorithm":"sha256","timestampUrl":"…"}}}'` → verify extracted bundle contents → package/upload. Delete the "Sign and verify GUI and installer" step and rewrite the verification step to 7z-extract the installer and assert `Get-AuthenticodeSignature` on every embedded `.exe`/`.dll` we own, with a hard failure if zero binaries are found.
**Rationale.** tauri-bundler already signs the main exe after `patch_binary` per package type (`settings.rs:609` `can_sign()`; `bundle.rs:155`), signs `externalBin` sidecars while skipping already-signed files (`bundle.rs:296-336`), signs NSIS plugins and the uninstaller (`nsis/mod.rs:672-679`, `:306`) and the outer installer (`:717`), and signs `resources/*` excluding already-signed files (`:792`) — so wintun's own signature is preserved. Authenticode and the Tauri updater signature are unrelated: `TAURI_SIGNING_PRIVATE_KEY`/`createUpdaterArtifacts` produce a **minisign** signature over the update archive and never sign the PE, doing nothing for SmartScreen.
**Alternatives considered.** `beforeBundleCommand` signing — works, but duplicates the bundler's own path and misses the uninstaller and NSIS plugins. Post-hoc signing plus re-inspection — rejected: cannot repair an already-embedded unsigned exe.
**Verification.** Build once with signing disabled and assert `verify-installers.ps1` exits non-zero; the "0 binaries found" fail-closed branch prevents a changed NSIS layout making the check vacuous.

### R30 — CI privileges, secrets and supply chain
**Decision.** `permissions: {}` at the top of both workflows with per-job least privilege (`contents: read`; publish adds `contents: write` + `id-token: write` and an `environment: release` with a required reviewer for tags). Move the Android keystore base64 into `env:` instead of interpolating into a `run:` line, with `::add-mask::`. Explicit file globs on every artifact upload (already `if-no-files-found: error`). Add `actions/attest-build-provenance@v2` for exe and APK. Track `packaging/*.sha256` and read the expected wintun digest from it rather than a hardcoded constant. `.gitignore` += `*.key`, `*.pem`, `*.pfx`, `*.crt`. Pin the vendored `quiche` tree with a checksum + `PATCHES.md`, or move to crates.io with `[patch]`. Add `zizmor`, `actionlint`, `actionlint`, `cargo deny`, `osv-scanner`, Dependabot, and keep pin-by-SHA.
**Rationale.** Measured repo shape: 2 433 tracked files, **2 147 under `quiche/` (88 %)**; the largest tracked binaries are `packaging/wintun.dll` (418 KB) and the three `libhev-socks5-tunnel.so` (~350 KB each). `rustup-init.exe` and the stray HTML review files are untracked — working-tree clutter, not a history problem, so no rewrite is needed. `zizmor` specifically catches the patterns present here: `template-injection`, `excessive-permissions`, `secrets-outside-env`, `overprovisioned-secrets`, `unpinned-images`.
**Alternatives considered.** `git subtree`/submodule conversion as a hard requirement — deferred: the pinned-checksum-plus-patch-manifest option delivers the audit property without churning every contributor's workflow.
**Verification.** Each gate ships `--selftest-fail`. Concretely: `zizmor` must flag the current `build.yml:304-305` before the fix and be clean after; a deliberately wrong `packaging/wintun.sha256` must fail the build.

### R31 — Mechanical invariant gates (`scripts/verify-invariants`)
**Decision.** A single CI job running: `cargo clippy -- -D warnings` with a `clippy.toml` `disallowed-methods` list for `Mutex::lock().unwrap()` in shell/engine paths; `#![deny(unsafe_op_in_unsafe_fn)]`; `grep 'std::env::var("AETHER_'` permitted only in the runtime-config module; **both-direction** IPC parity (registered commands vs `invoke` sites, failing on unused-and-unlisted as well as missing — today 5 commands are registered but never invoked); every serde enum variant handled in each TS switch; every `className` token resolving to a selector; stylelint forbidding `transition: all`, `100vh`, `border: 1px solid rgba(255,255,255,<0.10)`, bare `:hover`, and undefined `var(--x)`; a contrast script for the token palette; a fabricated-metric grep (R27).
**Rationale.** Every one of these corresponds to an audit class that recurred across three independent prior audit specs. The anti-tautology rule is the important one: the repo's three worst precedents are a CI step verifying the wrong artifact, a `build.rs` pinning a hash of the file it ships, and a tautological Android test.
**Verification.** `scripts/verify-invariants --selftest-fail` must exit non-zero. This is itself SC-013.

## E. Visual system and shared UI

### R32 — Fonts
**Decision.** `@fontsource-variable/geist` + `@fontsource-variable/geist-mono` (OFL-1.1; Vercel's `geist-font` license text is OFL-1.1 while the `geist` code package is MIT), imported from TS so Vite hashes the woff2 into `dist/` and keeps it same-origin under the existing `font-src 'self'`. Delete the Google Fonts `<link>`s. Do **not** use the Tauri `asset:` protocol.
**Rationale.** The CSP blocks the stylesheet and the font origin today, and there is no `@font-face` anywhere, so the packaged app has silently never used its own type system. `asset:` requires enabling and scoping the protocol plus `font-src asset: http://asset.localhost` — the wrong tool for build-time-known files. Subsetting is unnecessary; fontsource ships latin/latin-ext splits.
**Alternatives considered.** Relax the CSP to allow `fonts.gstatic.com` — rejected: a circumvention tool must not make a pre-tunnel third-party request from its UI, and must work offline.
**Verification.** Network assertions in the packaged build: zero non-`ipc:`/`localhost` requests; a build-time check that every `font-family` token has a matching `@font-face`.

### R33 — Borders that survive fractional scaling
**Decision.** `box-shadow: inset 0 0 0 1px var(--edge)` using **opaque, pre-resolved** colours, with two tokens: `--edge` (decorative panel separation, ≥1.6:1) and `--edge-interactive` (control boundaries, ≥3:1).
**Rationale.** The disappearance is caused by low alpha composited over differing backgrounds plus antialiasing of a 1 CSS px line at fractional scale (documented as far back as crbug.com/40896753); `calc(1px)`, `env()` and `@media (resolution:)` do not address it. WCAG 1.4.11 requires 3:1 only where the boundary is the sole means of identifying a control or its state — so a decorative separation gets a lower, honest floor while interactive edges meet 3:1.
**Alternatives considered.** Raise only the alpha values — rejected: still composited, still antialiased away at 150 %.
**Verification.** Measured-contrast script over the token set (BC-12) plus a screenshot diff at 100/125/150 %.

### R34 — Platform-correct rendering defaults
**Decision.** `color-scheme: dark` on `:root`, explicit `option` styling, `::selection`, `scrollbar-gutter: stable`, `@supports selector(::-webkit-scrollbar)` gating; `height: 100svh; height: 100dvh;` replacing all 8 `100vh`; `viewport-fit=cover` + `env(safe-area-inset-*)` on the mobile build; the desktop minimum width moved off the collision point (`minWidth: 901` or `@media (max-width: 899px)`); `@media (hover: hover) and (pointer: fine)` around all 27 hover rules; `.spin`/`.spin-icon` keyframes defined **outside** the reduced-motion block; touch targets ≥24 CSS px (WCAG 2.5.8) with 44 px preferred for primary controls.
**Rationale.** `scrollbar-gutter` is Baseline since December 2024, so it is safe in a 2026 WebView2. The `minWidth: 900` / `(max-width: 900px)` collision means a legal desktop window size matches the mobile block and hides the primary status widget.
**Alternatives considered.** `100vh` with JS measurement — rejected: reintroduces layout thrash and breaks under Android chrome.
**Verification.** Stylelint forbids the listed patterns; an automated check that no breakpoint equals a configured window minimum.

### R35 — Consolidate the UIs
**Decision.** Introduce a root workspace (there is none today — each app carries its own lockfile) with an `@aether/ui` package holding `tokens.css`, shared types and components. Platform differences (`platform`, watchdog enable/disable, hydration merge, scan wording) become **props**, not forks. Vite bundles it at build time, so CSP is unaffected.
**Rationale.** The two forks already differ in *behaviour* — only Android has the connect watchdog, only Android merges defaults — which is how a desktop user ends up permanently stuck in "Connecting" with the Settings tab locked. 359 differing CSS lines with one file defining `.spin` only inside a reduced-motion query is the same failure expressed visually.
**Alternatives considered.** A Vite alias to `apps/desktop/src` — rejected: leaves the dependency direction implicit and re-forks on the next divergence.
**Verification.** A CI diff that fails if `apps/desktop/src` and `apps/android/src` each define the same component name with different bodies.

### R36 — Virtualisation, boundaries, a11y widgets
**Decision.** `@tanstack/react-virtual` 3.x (`useVirtualizer`, `estimateSize` + `measureElement`, `overscan: 8`) for scanner rows; `content-visibility: auto` for the log view only. A class `ErrorBoundary` **per tab** inside its `role="tabpanel"` with `resetKeys={[tab, settingsLoadError]}` whose retry calls `refreshSettings()`. Segmented filter controls become an APG Radio Group (`role="radiogroup"`/`radio`, `aria-checked`, roving `tabIndex`, arrow-key cycling); `role="tablist"` is reserved for the real tab strip with `aria-controls`/`aria-selected`; `aria-live="polite"` + `role="status"` on the hero and the save dock; `tabIndex={0}` + `aria-label` on every scrollable region.
**Rationale.** react-virtual bounds DOM node count so per-row copy buttons do not mount thousands of effects (~10 kB gzip, no CSP impact); `content-visibility` skips paint/layout but never reduces node count, so it is not a substitute for windowing here. The APG requires exactly these roles; a non-focusable scroll container is simply not keyboard-scrollable, which is today's reality for the log console and the hits list.
**Alternatives considered.** Manual slice-and-paginate — rejected: loses measurement accuracy for variable-height rows. One app-level boundary — rejected: it is what currently white-screens the whole window on one bad payload.
**Verification.** An axe scan per tab with 2 000 mocked rows asserting zero role violations and DOM node count ≤ viewport+overscan; a test that a throwing `get_settings` mock shows the boundary UI whose Retry restores a working tab.

## F. Android platform

### R37 — Data-path liveness and handoff
**Decision.** (a) `configureTunBuilder()` **aborts** `establish()` if `addDisallowedApplication` throws. (b) Poll `TProxyGetStats()` every 5 s on the existing worker, baseline after `TProxyStartService`; treat `rx advancing && tx frozen` for 3 windows (15 s) as dead, and all-zero for 6 windows (30 s) as dead only when a foreground probe also fails. (c) On death: bump `vpnGeneration`, `TProxyStopService()`, close the fd, re-`establish()` and restart hev — capped at 3 attempts with 2/8/30 s backoff, then a terminal `status="error", detail="Network changed — reconnect required"` with no further auto-retry until the user taps connect. (d) Make `markConnected()` re-evaluable (`resetConnected()`), driven by the watchdog. Do **not** attempt re-`protect()`.
**Rationale.** Upstream `native_get_stats` returns `[tx_packets, tx_bytes, rx_packets, rx_bytes]` and zeroes them on each `hev_socks5_tunnel_main()` entry, with `rx` counting tun reads and `tx` counting tun writes — so a QUIC socket bound to a dead interface produces precisely "rx advancing, tx frozen". AOSP documents `setUnderlyingNetworks` as needing a call on every network-set change and as succeeding only while established; it does **not** migrate already-bound sockets. `protect(int)` operates on an fd in the caller's table, and the engine is a `ProcessBuilder` child, so its fds never exist in this process. Shipped precedent restarts: v2rayNG's `restartCallback = { runTun2socks() }`, WireGuard-Android's teardown-and-re-establish.
**Alternatives considered.** In-process JNI now — rejected for this feature: `addDisallowedApplication` already covers loop avoidance for our own UID, the exec-from-`nativeLibraryDir` path exists precisely because `filesDir` exec is blocked, and the 12 s stdio protocol would need a full rewrite. Phase 2 option: a `LocalServerSocket` + `SCM_RIGHTS` fd handoff, which would make `protect()` possible since same-UID fds are accepted by netd. `addAllowedApplication` — rejected: semantically inverted and throws if the disallowed form is already in use.
**Verification.** Unit-test `configureTunBuilder()` against a fake builder that throws, asserting `establish()` is never called and the state becomes an error (today it silently succeeds). Table-drive a pure `decideLiveness(prev, now, elapsed, attempt)` across rx↑/tx=0, all-zero, healthy and attempts-exhausted, wired into a Robolectric test asserting `TProxyStopService`/`establish` are actually re-invoked.

### R38 — Bridge, threading and lifecycle
**Decision.** Make the bridge asynchronous: `invoke(cmd, argsJson, requestId)` returns immediately, work is dispatched onto a `CoroutineScope(SupervisorJob() + Dispatchers.IO)`, and results resolve via `evaluateJavascript("__aetherResolve(<id>,<json>)")`, with `bridge.ts` holding a `Map<id, resolver>` and a 30 s timeout. **Coroutines** are the module's single concurrency model (the dependency already exists but is unused). `SessionController` holds a `@Volatile` emitter plus a `CopyOnWriteArrayList` of listeners registered in `onStart`/unregistered in `onStop`; `MainActivity` uses `registerForActivityResult` and `launchMode="singleTask"`; `onRevoke` only sets flags and posts to the scope; the 150 ms join runs off-main.
**Rationale.** `@JavascriptInterface` methods run on the WebView's JavaBridge thread and JS blocks on the return value; from there the code currently calls main-thread-only `VpnService.prepare()`/`startActivityForResult`, polls with `Thread.sleep(50)` up to 5 s, and runs a 12 s synchronous OkHttp `execute()`. AOSP documents that `onRevoke` "may not happen on the main thread" and requires closing the fd. Note: `stopProtected()`, cited in one prior audit note, **does not exist** in AOSP `VpnService`/`Service` — it is not available to plan around.
**Alternatives considered.** Capacitor's plugin layer — rejected: adds a runtime and config for one bridge. `WebMessageListener`/`postMessage` — cleaner origin scoping but needs a JS port handshake and is unusable before page load; keep `evaluateJavascript` correlation. WorkManager for teardown — rejected: wrong tool for a 150 ms join.
**Verification.** `runTest` with a fake WebView asserting `invoke` returns in <50 ms while a 12-second stub blocks behind it, and that every request id is resolved exactly once (success or timeout). A two-activity test asserting `onStop` of A leaves B's listener receiving events.

### R39 — Keystore policy and supervision
**Decision.** Retry `getOrGenerate` 3× (200 ms/1000 ms) on `KeyStoreException|ProviderException|UnrecoverableKeyException`, then **throw** — never delete. Only `BadPaddingException`/a short-buffer decode may trigger rotation, and rotation first writes a second wrapping: `wrappedA` under `…-v1` and a mirror `wrappedB` under `…-v2`, refreshed on alternating boots, B written last, both validated before promoting. Replace the `require(b.size >= 12+16)` with an explicit length check returning a distinct `CorruptWrappingException`. Keep `setUserAuthenticationRequired(false)` + `setInvalidatedByBiometricEnrollment(false)`, add `setRollbackResistant(true)` guarded at API 33+. `EngineService` → `START_STICKY` with `onTaskRemoved { stopSelf() }`, a partial wake lock only while connected, and a periodic keep-alive via `WorkManager`. `disconnect()` propagates failure and can report `disconnect_incomplete`.
**Rationale.** AndroidKeyStore keys are per-app-and-user-credential and survive app updates — they die on uninstall/restore/factory reset — so an `UnrecoverableKeyException` on `getKey` after a `keystore2` restart is retryable, whereas `BadPaddingException` is the signal that *data*, not the key, is bad. The current catch-all routes every one of these into deleting the alias and quarantining the config.
**Alternatives considered.** `KeyStore.wrap`/`unwrap` for exportable backup — rejected: needs a `KeyPair` KEK and a keystore dependency for one blob. EncryptedSharedPreferences — rejected: deprecated, and it does not fix the auto-delete policy. `START_NOT_STICKY` with manual user reconnect — rejected: the VPN must survive a process kill.
**Verification.** Fixture tests: `UnrecoverableKeyException` twice then success → recovery succeeds, alias **not** deleted, config intact; `BadPaddingException` → quarantine happens. That is the reachability proof in both directions.

### R40 — Status from events, not prose
**Decision.** Delete all log-substring matching and consume `AETHER_EVENT` structured events only, fail-closed to `disconnected`: `connected{detail}` is the sole proof, `proxy_ready` + `tunnel_ready` gate `connecting`, and `error` or process exit ⇒ `error`.
**Rationale.** The Kotlin matcher looks for `"handshake successful"`, a string that does not exist in the Rust source — the guard's trigger is unreachable, which is the audit's signature defect expressed in the status path.
**Verification.** A parser test asserting every `SessionEvent` variant maps to a defined state and that an unknown variant yields `disconnected`.

### R41 — Android build compliance
**Decision.** `compileSdk`/`targetSdk` = 36, AGP ≥ 8.7, `enableEdgeToEdge()` + `WindowInsetsCompat` padding, delete `android:statusBarColor`/`navigationBarColor` from `themes.xml`, `isShrinkResources = true`. Drop `useLegacyPackaging`/`extractNativeLibs="true"` in favour of `extractNativeLibs=false` plus AGP's 16 KB zip alignment, and add `RUSTFLAGS="-C link-arg=-Wl,-z,max-page-size=16384 -C link-arg=-Wl,-z,common-page-size=16384"` to the `cargo ndk` step (NDK r27d does **not** default to 16 KB). Commit `apps/android/hev-lock.json` (upstream tag + per-ABI sha256 + build recipe) and **build `libhev-socks5-tunnel` from that tag in CI**, verifying `readelf -l` `p_align ≥ 0x4000` and the expected JNI symbols; replace `test -s` with `sha256sum -c`. Fix the favicon path, add a monochrome `ic_notification`, bump `webkit` and `okhttp`, delete the coroutines dependency only if the R38 decision does not adopt it (it does), and replace the tautological test with Robolectric `ShadowVpnService` builder-argument capture and `ShadowConnectivityManager` callback tests.
**Rationale.** Play requires target API 36 for new apps and updates from 2026-08-31 (extendable to 2026-11-01); 16 KB page-size support is enforced from 2027-02-01 for apps targeting 35+, and `useLegacyPackaging` fixes installation only, not ELF alignment. The committed `.so` blobs are already 0x4000-aligned but untraceable — their strings reveal JNI signatures that differ from upstream (a `void` `TProxyStartService` and **no** `TProxyIsRunning`) and a source directory absent from this repo, so provenance cannot be established from what is committed. Android 15 excludes `specialUse` from the `BOOT_COMPLETED` FGS ban, so `BootReceiver` stays legal, and VPN apps must satisfy Play's declaration and prominent-disclosure policy. Note that `RUSTSEC-2023-0071` is the **`rsa` Marvin** advisory, not a `ring` one: the `ring 0.16.20` duplicate pulled via `boringtun 0.6.0` is an EOL/duplicate-crate risk, not a known vulnerability, and is recorded as such.
**Alternatives considered.** Keep the prebuilt blobs and add checksums only — rejected: checksums without provenance prove nothing about what produced the bytes.
**Verification.** CI fails when any `jniLibs/**/*.so` has `p_align < 0x4000` or an unexpected sha256 — proven reachable by corrupting the lock file in the same PR run. A screenshot/instrumentation check that the primary control has non-zero visible bounds after insets are applied.

## G. Engine packaging

### R42 — One module owner
**Decision.** `lib.rs` is the single module owner; `main.rs` becomes `fn main() -> aether::run()` so the shipped binary is the same code the integration tests exercise. Delete the orphan `mac_test.rs` (referenced by no `mod`, so never compiled). Remove `ACL_FAIL_FOR_TEST` from shippable code, or gate it `#[cfg(any(test, feature = "dev"))]`.
**Rationale.** `main.rs` currently compiles its own private copy of all 30 modules, which is why `aether/tests/*` can pass against library code that the shipped binary does not contain. A `pub static` test knob in a release binary is a live failure injection point in a process that writes secrets.
**Verification.** A build test asserting `aether::` symbols are present in the produced binary, and a grep gate that no `pub static` `AtomicBool` exists outside `#[cfg(test)]`.
